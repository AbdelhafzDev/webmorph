## 2. What is genuinely solid

- **Evidence discipline.** Every capability, fact and hypothesis carries artifact references. The model cannot alter mechanics. Tools are data.
- **Safety at the network layer.** The same scope and SSRF policy applies to the HTTP client and to every browser request, including subframes and subresources.
- **Read-only by construction.** No probe or tool can submit a POST form without an explicit operator flag, and even then only search or filter forms without sensitive fields. The fixture asserts zero POSTs across the whole pipeline.
- **Verification against reality.** Every phase was run against live sites, and each live run found a defect the fixture had missed (trailing-slash redirects, SPA false positives, transpiler helper injection, header-search misclassification, empty search queries).
- **Failure is data.** Blocked sites, broken markup, moved endpoints and missing credentials all end as recorded outcomes rather than exceptions.

## 3. Findings

Severity: high means wrong results or unsafe behavior on real sites; medium means degraded quality or a maintenance trap; low is cleanup.

### Author's findings

| # | Severity | Where | Finding | Action |
|---|---|---|---|---|
| A1 | medium | `src/tools/interpreter.ts` wait step | `wait: navigation` compares against the URL read when the wait step starts, not before the action that triggered the navigation. If the navigation commits before the wait step runs, the step waits for a second navigation and fails with `SITE_CHANGED`. Passes today only because `noWaitAfter` returns before commit | Track the URL before each action and compare against that |
| A2 | medium | `src/stages/stage10-validate.ts` stability check | `stable-across-runs` compares count and first URL. Sites with randomized or recency-ordered listings will fail validation permanently | Compare counts and set overlap, not order |
| A3 | medium | `src/core/job.ts` resume | A stage that produced some artifacts then crashed cannot be resumed: the runner would re-run it and hit the immutable-artifact guard | Treat a stage as resumable only if none of its artifacts exist; otherwise require a new job |
| A4 | low | `src/browser/collect.ts` text uniqueness | `counts.text` counts interactive elements only, but `getByText` matches any element, so a link whose text equals a heading is reported unique when it is not | Count across all elements with that text |
| A5 | low | `src/stages/stage4-plan.ts`, `src/browser/inspect.ts`, `src/model/facts.ts`, `src/cli.ts` | Dead code: an `&& false` guard, `void` statements silencing unused values, an unused import kept alive with `void` | Remove |
| A6 | low | `src/model/facts.ts` entity naming | Entities come only from URL patterns. A site with `/item?id=123` style detail pages yields no entity, no list tool and no detail tool | Phase 5 or later: derive entities from JSON-LD types and listing link structure as well |

Test gaps the reviewer listed are now covered: browser SSRF branch with a custom resolver, document and subresource redirects to out-of-scope and private hosts, transient error then redirect, resume, prohibited paths in both the HTTP client and the browser, JS-driven writes, deep-DOM locator uniqueness, trailing-slash crawling, a non-UTF-8 page, write probes behind the flag, and the Claude client's refusal and truncation mapping.

## 4. Fixes applied in this review

Twenty findings were addressed (A1 to A5, R1 to R15); A6 and A4 are recorded as known limits. The suite grew from 125 to 140 tests, all passing, and a live HTTPS run confirmed the proxy path. The remaining documented gap in the browser path is that an out-of-scope public document reached through a redirect is refused at the hop, while a public third-party subresource is still allowed, as the policy intends.

Two things changed in what the README claims. Browser requests are now enforced at two layers, connection and request, and the route layer performs each fetch itself with redirects disabled. Write requests from page JavaScript are refused by default; this is what makes "read-only by construction" true rather than merely intended.

## 5. Readiness for Phase 4

The adapter needs three things the codebase already has: a tool contract (`ToolSpec`), an executor with a typed error taxonomy (`executeTool`), and a validation verdict per tool. What it adds is a mutable registry pinned to artifact versions, an approval gate, pooled execution, and call-time policy. Nothing in sections 3 or 4 blocks that work.
